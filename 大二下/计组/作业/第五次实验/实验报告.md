（1）掌握单总线结构MIPS处理器（硬布线控制器、微程序控制器）、单周期MIPS处理器（硬布线控制器）、单周期RISC-V处理器（硬布线控制器）设计的基本原理。

### 回答问题

#### （1）针对test1.asm程序段

![image-20260525145038904](./%E5%AE%9E%E9%AA%8C%E6%8A%A5%E5%91%8A.assets/image-20260525145038904.png)

为何上述两条指令不会执行到？

因为前面的 `beq $zero,$zero,loop2` 会无条件跳转到 `loop2`，随后 PC 会一直在 `loop2` 处循环，不再按顺序执行后面的两条指令。截图中的运行结果也印证了这一点：RAM 的 `102` 单元最终写入的是前面 `sw $s3,1032($zero)` 的结果 `00000001`，而不是 `loop1` 中准备写入的数值。也就是说，程序控制流在进入 `loop2` 后已经被固定住，后续指令地址虽然仍在存储器中，但实际上不会被取到和执行。



#### （2）为何安排死循环？若不采用死循环，针对此种情况，MIPS架构还可以采用什么方式？（课外扩展）

实验电路中没有操作系统，也没有专门的 `halt` 指令，因此程序如果“自然结束”，PC 还会继续向后取指，可能读到未定义的存储单元内容，造成不可预期的执行结果。安排死循环的作用，就是让处理器停留在一个确定的、可观察的结束状态，便于查看 RAM、寄存器和周期数。若不采用死循环，在完整的 MIPS 体系中还可以通过 `syscall`、`break`、异常或陷入处理等方式结束程序，由系统接管后续流程。



#### （3）在该单总线结构 MIPS 处理器（硬布线控制器）的数据通路上，能够运行 求累加和程序、 计算费波那契数列程序吗？为什么？

不能完整运行。因为这两个程序都需要寄存器之间的加法运算，例如累加和程序中的 `add $s3,$s3,$s1`，以及 Fibonacci 程序中的 `add $s6,$s4,$s5`。而原 5 条指令版本只支持 `lw`、`sw`、`beq`、`slt`、`addi`，其中 `addi` 只能完成寄存器与立即数相加，不能代替 add 指令完成两个寄存器操作数的加法。因此在未扩展 add 指令之前，这两类程序无法在该数据通路上正确执行。

#### （6）结合工作原理，比较下述微程序控制器和硬布线控制器引脚上的不同

微程序控制器的引脚除了时钟、复位和条件输入外，还需要与“微地址/状态”相关的接口，用来给出当前微指令地址并控制下一微地址的选择，因此它体现的是“由控制存储器读出控制字”的工作方式。硬布线控制器则更多体现为状态信号、译码信号和条件信号输入，再直接输出控制总线与状态节拍信号，本质上是组合逻辑加状态机驱动。前者便于修改和扩展指令，只需调整微程序或入口逻辑；后者不依赖控制存储器，结构更直接，速度通常更快，但新增指令时需要重新设计状态与逻辑。两者引脚差异正反映了两种控制方式在实现机制上的不同。

#### （9）该单周期 MIPS 处理器的控制器能不能采用微程序控制器的方法设计？为什么？

理论上可以借鉴微程序“按步骤产生控制信号”的思想，但不适合本实验中的单周期处理器。因为单周期结构要求一条指令在一个时钟周期内完成取指、译码、执行、访存和写回，而微程序控制通常需要多个微周期逐步完成这些动作。若强行采用典型微程序方式，就会把一条机器指令拆成多步执行，从而破坏单周期处理器的基本定义。因此本实验中的单周期 MIPS 更适合采用硬布线组合逻辑直接生成控制信号。

该电路的输入主要是指令中的 `opcode`、`funct` 等字段，输出则包括 `RegDst`、`ALUSrc`、`MemtoReg`、`RegWrite`、`MemRead`、`MemWrite`、`Branch`、`Jump`、`ALUOp` 等控制信号。控制器先根据 `opcode` 区分指令大类，例如访存类、分支类、R 型指令和跳转类，再结合 `funct` 进一步确定 R 型指令对应的具体 ALU 运算。随后这些控制信号分别送往寄存器堆写地址选择器、ALU 输入选择器、数据存储器读写使能以及 PC 更新通路，使数据通路按照当前指令要求工作。也就是说，该模块本质上是“对指令字段做组合译码，再把译码结果分发到各功能部件”。



#### （11）单周期 RISC-V 处理器的控制器能不能采用微程序控制器的方法设计？为什么？

同样地，理论上可以用微程序思想描述控制过程，但不适合单周期 RISC-V 处理器。因为本实验中的单周期 RISC-V 也是要求一条指令在一个时钟周期内完成全部操作，而微程序控制通常依赖多个微周期来顺序发出控制信号。若采用传统微程序方式，就会把单周期结构改造成多周期结构，不再符合原有设计目标。因此本实验的 RISC-V 控制器更适合用硬布线逻辑根据 `opcode`、`funct3`、`funct7` 等字段直接生成控制信号。



#### （12）请分析单周期 RISC-V处理器（硬布线控制器）的下述电路原理：

a)ALU控制信号生成部件

![image-20260525145159491](./%E5%AE%9E%E9%AA%8C%E6%8A%A5%E5%91%8A.assets/image-20260525145159491.png)

b)立即数扩展部件

RISC-V 的 ALU 控制信号生成部件以 `opcode`、`funct3`、`funct7` 等指令字段作为输入，判断当前应执行的是 add 指令、`slt`、`sltu`、`ori` 等哪一种运算，再输出对应的 `ALUctr` 去控制 ALU。这样即使不同指令的大类相同，只要功能字段不同，ALU 仍能执行正确的具体操作。立即数扩展部件则根据指令格式对立即数字段进行提取和拼接，例如 I 型、S 型、B 型、J 型指令的立即数字段位置各不相同，扩展部件需要按照格式规则组合并进行符号扩展，最后输出 32 位立即数。该立即数可用于 ALU 运算、访存地址计算以及分支跳转目标地址的形成，因此它是单周期 RISC-V 数据通路中的关键部件。
