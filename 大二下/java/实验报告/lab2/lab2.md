## 二、实验题目及实现过程

#### 1. 实验题目

- **基本题目：** 随机生成六个筛子点数，并根据博饼游戏规则判断得奖情况（需处理多奖项并存的情况）。
- **扩展题目：** 完善游戏逻辑，实现多玩家（6-10人）轮流摇骰，维护游戏奖项库存（Inventory），并在奖项发完后终止游戏并进行结算 。

#### 2. 实现过程与逻辑设计

在实现过程中，我主要采用了以下核心策略：

- **奖项判断逻辑 (`judgePrizes` 方法)：**
  - 通过定义 `int[] counts` 数组记录 1-6 点数的出现次数，以便快速判断不同奖项的触发条件。
  - 针对六子博饼规则，利用 `IntStream` 对点数分布进行统计 。例如，判断“对堂”时通过 `allMatch` 检查每个点数是否各出现一次；判断“状元”时分别处理了“四个四”和“五子”的情况。
  - 由于博饼允许“多奖并存”，代码中未使用 `if-else`，而是为每个奖项设置独立的 `if` 条件，确保单次投掷能同时触发多个符合规则的奖项 。
- **游戏流程控制：**
  - 使用 `Map<Prize, Integer>` 作为全局 `INVENTORY`，严格按照题目要求的奖项份数进行库存管理 。
  - 通过 `while(hasPrizes())` 循环控制游戏进程，确保在所有奖项被领完前持续进行，通过 `turn % playerCount` 实现玩家轮流投掷 。
- **数据结构选择：**
  - 利用 Java 的 `record` 关键字定义 `Player` 类，简洁地存储每个玩家的 ID 及已获得的奖项记录。
  - 投掷骰子部分使用了 `Random.ints(6, 1, 7)` 快速生成符合范围的随机数 。

## 三、实验总结与心得记录

#### 1. 实验核心逻辑总结

本实验通过 Java 编程完整实现了博饼游戏的数字化模拟。在实现过程中，我重点解决了以下技术问题：

- **多奖项判定的严谨性：** 博饼规则中存在“多奖并存”的情况（如“四进带一秀”）。我通过使用多个独立的 `if` 分支而非 `if-else` 结构，确保了程序能够捕获单次投掷中产生的所有合法奖项 。
- **游戏生命周期管理：** 利用 `Map` 容器维护奖项库存，并结合 `while` 循环和取模运算（`turn % playerCount`）实现了多玩家公平轮流投掷，直到奖项库存耗尽为止，保证了游戏逻辑的完整性 。

#### 2. Java 技术应用心得

- **函数式编程的便利：** 在统计骰子点数和判断奖项时，我大量使用了 `IntStream` 和 `Lambda` 表达式。相比传统的嵌套循环，`anyMatch`、`allMatch` 以及 `filter` 等方法显著提高了代码的可读性和开发效率 。
- **新特性尝试：** 实验中尝试使用了 Java 16+ 引入的 `record` 类型来定义玩家数据结构，这使得数据载体类的编写变得极其简洁，避免了冗长的 Getter 和 Setter 代码 。
- **解耦设计：** 将奖项判断逻辑抽离到 `judgePrizes` 静态方法中，实现了逻辑与显示的解耦，便于后续对规则进行维护或扩展。

#### 3. 实验反思与改进

通过本次实验，我深刻体会到在处理具有复杂规则的游戏逻辑时，**数据结构的设计**至关重要。最初在处理奖项库存时曾考虑使用数组，但最终选择 `HashMap` 是因为它在处理“名称-剩余数量”这类映射关系时更加直观且易于维护。

此外，实验也提醒我在编写交互式程序时，必须考虑到**用户输入的健壮性**，例如在获取玩家人数时加入了类型检查和范围限制，以防止程序因非法输入而崩溃 。
