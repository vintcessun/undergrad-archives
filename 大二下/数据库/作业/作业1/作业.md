# 第1章作业

## 题目

### 1. 试述数据、数据库、数据库管理系统、数据库系统的概念。

- **数据**：描述事物的符号记录，是数据库中存储的基本对象。它可以是数字、文字，也可以是图形、图像、音频等。
- **数据库**：长期储存在计算机内、有组织的、可共享的大量数据的集合。数据库中的数据按一定的数据模型组织、描述和储存。
- **数据库管理系统**：位于用户与操作系统之间的一层数据管理软件。它负责科学地组织和存储数据、高效地获取和维护数据。
- **数据库系统**：由计算机硬件、操作系统、数据库管理系统（及其应用开发工具）、数据库、应用程序和数据库管理员组成的完整运行实体。

### 2. 试述文件系统与数据库系统之间的区别和联系。

- **联系**：
  - 两者都是计算机系统中管理数据的软件。
  - 都由数据管理软件来管理数据，程序和数据之间都有一定的独立性。
  - 数据都长期保存在外存上。
- **区别**：
  - **结构化程度**：文件系统中的文件内部有结构，但文件与文件之间没有联系，整体是无结构的；数据库系统不仅内部有结构，整体也有结构（数据之间有联系）。
  - **冗余度与共享性**：文件系统数据冗余度大，共享性差；数据库系统数据共享性高，冗余度低。
  - **数据独立性**：文件系统的独立性较差（程序依赖于文件的数据结构）；数据库系统具有高度的物理和逻辑独立性。
  - **控制能力**：文件系统控制能力弱；数据库系统由DBMS提供统一的数据安全性、完整性、并发控制和恢复功能。

### 3. 分别举出适合用文件系统的应用例子，以及适合用数据库系统的应用例子。

- **适合文件系统的例子**：
  - **操作系统中的日志记录**：只需按时间顺序追加写入，不需要复杂的查询和关联。
  - **个人的临时备忘录或文本文件**：数据量小，结构简单，仅供个人单机使用，无需共享。
  - **视频/音频原始文件存储**：这类多媒体大文件通常直接交由文件系统管理，数据库中只存储它们的路径和元数据。
- **适合数据库系统的例子**：
  - **银行储蓄系统**：需要处理海量交易，要求极高的数据一致性、并发控制和安全性。
  - **大型电子商务平台（如淘宝、京东）**：涉及商品、用户、订单之间极其复杂的关联关系和高并发查询。
  - **医院信息管理系统 (HIS)**：医生、病人、药品、病历等数据相互交织，需要高度结构化和跨科室共享。

### 4. 试述数据库系统的特点。

1. **数据结构化**：这是数据库系统与文件系统的根本区别。不仅数据内部结构化，整体数据也是结构化的。
2. **数据的共享性高，冗余度低且易扩充**：由于数据面向整个系统而非单一应用，多个用户可以共享同一数据，大大减少了重复存储。
3. **数据独立性高**：包含物理独立性（物理存储改变不影响程序）和逻辑独立性（逻辑结构改变不影响程序）。
4. **数据由DBMS统一管理和控制**：提供安全性保护、完整性检查、并发控制和数据库恢复等机制。

### 5. 数据库管理系统的主要功能有哪些？

1. **数据定义功能**：提供数据定义语言，让用户定义数据库的三级模式、完整性约束等。
2. **数据组织、存储和管理**：分类组织、存储和管理各种数据（包括数据字典、用户数据等），提高存储和检索效率。
3. **数据操纵功能**：提供数据操纵语言，实现对数据的增、删、改、查基本操作。
4. **数据库的事务管理和运行管理**：保证数据的安全性、完整性、并发控制以及故障后的系统恢复。
5. **数据库的建立和维护功能**：包括数据库初始数据的输入/转换、转储/恢复、性能监视和分析等。

### 6. 什么是概念模型？试述概念模型的作用。

- **概念模型**：也称信息模型，它是按用户的观点来对数据和信息建模，主要用于数据库设计。它是对现实世界的第一层抽象。
- **作用**：概念模型是现实世界到机器世界的一个过渡中间层。它既便于用户理解（不涉及底层的计算机硬件和具体的DBMS），又容易转换为具体的DBMS所支持的数据模型。它是数据库设计人员和用户之间进行交流的语言。

### 7. 定义并解释概念模型中以下术语：实体，实体型，实体集，实体之间的联系

- **实体**：客观存在并可相互区别的事物。比如“张三”这个学生，或者“一门具体的课程”。
- **实体型**：具有相同属性的实体具有相同的特征和性质，用实体名及其属性名集合来抽象和刻画同类实体。例如：学生（学号，姓名，性别，年龄）。
- **实体集**：同一类型实体的集合。例如：学校里所有的学生。
- **实体之间的联系**：现实世界中事物内部或事物之间的联系在信息世界中反映为实体内的联系和实体间的联系。实体间的联系通常分为一对一 (1:1)、一对多 (1:n) 和多对多 (m:n) 三种。

### 8. 试述数据模型的概念、作用及其包含的三个要素。

- **概念**：数据模型是对现实世界数据特征的抽象，也就是用来描述数据、组织数据和对数据进行操作的数学概念集合。
- **作用**：它是数据库系统的核心和基础，决定了DBMS的功能和性能。它为数据库提供了统一的数据描述规则。
- **三要素**：
  1. **数据结构**：描述系统的静态特性（如关系模型中的二维表）。
  2. **数据操作**：描述系统的动态特性（如对数据的增删改查）。
  3. **数据的完整性约束条件**：一组完整性规则的集合，规定数据必须符合的语义和规则（如主码不能为NULL）。

### 9. 试述层次模型的概念，举出三个层次模型的实例。

- **概念**：用树形结构来表示各类实体以及实体间联系的模型。它满足两个条件：有且只有一个节点没有双亲节点（根节点）；其他节点有且只有一个双亲节点。
- **实例**：
  1. **公司的行政组织架构**：董事长 -> 各部门经理 -> 基层员工。
  2. **家族族谱**：祖先 -> 父辈 -> 子孙。
  3. **计算机操作系统的文件目录结构**：根目录 (C盘) -> 文件夹 -> 子文件夹及文件。

### 10. 试述网状模型的概念，举出三个网状模型的实例。

- **概念**：用图结构来表示实体及实体间联系的模型。它允许一个以上的节点无双亲，也允许一个节点有多个双亲（打破了树形结构的限制）。
- **实例**：
  1. **教师与学生的授课关系**：一个老师教多个学生，一个学生听多个老师的课。
  2. **零件与供应商的关系**：一个零件可由多个供应商提供，一个供应商可提供多种零件。
  3. **城市间的航线网络**：多个城市之间相互通航，没有唯一的“根”城市。

### 11. 试述网状数据库、层次数据库的优缺点。

| **模型**     | **优点**                                                     | **缺点**                                                     |
| ------------ | ------------------------------------------------------------ | ------------------------------------------------------------ |
| **层次模型** | 1. 结构简单清晰。 2. 检索效率高（路径固定）。 3. 提供了良好的完整性支持。 | 1. 难以表示多对多 (m:n) 的联系。 2. 插入和删除操作限制多（比如删父必删子）。 3. 结构不够灵活。 |
| **网状模型** | 1. 能够更直接地描述现实世界（如m:n关系）。 2. 具有良好的性能，存取效率高。 | 1. 结构极度复杂，随着应用扩大难以维护。 2. DDL和DML语言复杂，用户需要了解物理存取路径，不易使用。 |

### 12. 试述关系模型的概念，定义并解释以下术语：关系，属性，域，元组，码，分量，关系模式

- **关系模型**：建立在严格的数学概念基础上，用二维表的形式表示实体以及实体间联系的数据模型。
- **关系**：一个关系对应通常说的一张二维表。
- **属性**：表中的一列即为一个属性。
- **域**：属性的取值范围（例如“性别”的域是{男, 女}）。
- **元组**：表中的一行即为一个元组（代表一个具体的实体记录）。
- **码**：也称为键。表中的某个属性组，它可以唯一确定一个元组（如“学号”）。
- **分量**：元组中的一个属性值（即表格中的一个具体单元格内的数据）。
- **关系模式**：对关系的描述，通常表示为：关系名(属性1, 属性2, ..., 属性n)。

### 13. 试述关系模型的优缺点。

- **优点**：
  - 建立在严格的数学概念之上。
  - 概念单一，数据结构简单、清晰（一切都是二维表）。
  - 存取路径对用户透明，具有更高的数据独立性和更好的安全保密性，极大降低了开发难度。
- **缺点**：
  - 由于存取路径透明，查询效率往往不如非关系数据模型（特别是涉及多表连接操作时）。
  - 增加了系统在查询优化上的负担，对DBMS的性能要求较高。

### 14. 试述数据库系统的三级模式结构，并说明这种结构的优点是什么。

- **外模式**：也称子模式或用户模式，是数据库用户能够看见和使用的局部数据的逻辑结构和特征的描述（如视图）。
- **模式**：也称逻辑模式，是数据库中全体数据的逻辑结构和特征的描述，是所有用户的公共数据视图。
- **内模式**：也称存储模式，是数据物理结构和存储方式的描述，是数据在数据库内部的组织方式。
- **优点**：保证了数据与程序的极大独立性，简化了用户接口，有利于数据的安全保密，同时使得数据库的设计和维护更加灵活。

### 15. 试述数据与程序的物理独立性和逻辑独立性。为什么数据库系统具有较高的数据与程序的独立性？

- **物理独立性**：指用户的应用程序与数据库中数据的物理存储是相互独立的。当数据的物理存储改变（如更换存储设备、改变存取方法）时，应用程序不用改变。
- **逻辑独立性**：指用户的应用程序与数据库的逻辑结构是相互独立的。当数据的逻辑结构改变（如增加新属性）时，应用程序不用改变。
- **原因**：数据库系统通过在三级模式之间提供**两级映象**（外模式/模式映象、模式/内模式映象）来保证独立性。当物理存储改变时，只需修改“模式/内模式映象”；当全局逻辑结构改变时，只需修改“外模式/模式映象”。这样就将底层变化与上层应用隔离开了。

### 16. 试述数据库系统的组成。

数据库系统一般由以下五个核心部分组成：

1. **数据库**：存储数据的“仓库”。
2. **数据库管理系统**：管理和操作数据库的核心软件。
3. **应用程序**：建立在DBMS之上，利用数据库满足特定业务需求的软件系统。
4. **硬件平台及数据库**：支持DB和DBMS运行的计算机硬件设备（CPU、内存、大容量磁盘等）。
5. **人员**：包括数据库管理员、系统分析员、数据库设计人员、应用程序员和最终用户。其中 DBA 负责整个系统的全面管理和控制。
